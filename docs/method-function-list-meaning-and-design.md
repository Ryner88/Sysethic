# Method, Function, List Meaning, and Design

This document explains the main functions, in-memory lists, caches, and design intent in `web/saaoe_api.py`.

## Runtime Design

SAAOE currently uses a single Flask process with:

- HTML page routes that render templates.
- JSON API routes that provide live telemetry, anomalies, reports, automation, files, and security data.
- A background sampler thread that keeps short ring buffers for live CPU, memory, disk, and network metrics.
- In-memory rule stores for anomaly rules, automation rules, playbooks, and run history.
- A development diagnostic WebSocket server that starts only when `web/saaoe_api.py` is run directly.

The design favors a lightweight local monitoring dashboard. Production use should add authentication, durable storage, stronger audit logging, and a hardened terminal channel.

## Core Data Lists and Caches

### Telemetry Ring Buffers

- `cpu_series`: recent CPU percent samples.
- `mem_series`: recent memory percent samples.
- `usage_ts`: timestamps matching CPU and memory samples.
- `read_series`: recent disk read MB/s samples.
- `write_series`: recent disk write MB/s samples.
- `disk_ts`: timestamps matching disk samples.
- `rx_series`: recent network receive MB/s samples.
- `tx_series`: recent network transmit MB/s samples.
- `net_ts`: timestamps matching network samples.

Meaning: these lists power live charts, Visualization Lab plots, and dashboard metric cards.

Design note: they are `deque` instances with `MAX_SAMPLES`, so memory stays bounded.

### Rule and Workflow Lists

- `anomaly_rules`: custom threshold rules checked against latest telemetry.
- `playbooks`: response definitions that match anomalies and describe actions.
- `playbook_runs`: recent playbook response run records.
- `automation_rules`: conditional automation rules based on anomaly fields.
- `automation_history`: recent automation actions generated by matching rules.

Meaning: these are current in-memory workflow stores.

Design note: they should move to durable storage before production use.

### Runtime Caches

- `_PROCS_CACHE`: short-lived cache for process table reads.
- `_threat_intel_cache`: mtime-aware cache for parsed local threat intel JSON.
- `_files_access_cache`: short-lived cache for `/api/files/access` filesystem scans.

Meaning: these reduce repeated expensive host or filesystem operations.

Design note: cache TTLs and invalidation should be tuned for deployment size.

## Function Reference

### Sampling and Host Inspection

`sampler()`

- Runs as a daemon thread.
- Samples CPU, memory, disk, and network metrics.
- Updates telemetry ring buffers.
- Pushes high/critical anomaly notifications into `notification_queue`.

`_top_procs(n=5)`

- Reads process metadata through `psutil`.
- Returns top CPU and memory processes.
- Uses `_PROCS_CACHE` to avoid expensive repeated process scans.

`_read_temps()`

- Reads host temperature sensors when supported.
- Returns an empty list if sensors are unavailable.

`_read_gpus()`

- Reads GPU load, memory, and temperature using optional `GPUtil`.
- Returns `available: false` when the library or GPU data is unavailable.

`_local_ipv4_addresses()`

- Lists local IPv4 addresses from network interfaces.

`_local_connection_summary()`

- Summarizes listening and established local network connections.

`_bytes_to_gb(value)`

- Converts byte counts into rounded GB values for UI cards.

## Threat Intelligence Functions

`_load_threat_intel()`

- Reads the configured threat intel JSON file.
- Normalizes missing or invalid files into empty `ips`, `domains`, and `hashes` maps.

`_get_cached_threat_intel()`

- Returns cached threat intel data.
- Reloads only when the source file mtime changes.

`_threat_lookup(indicator_type, indicator)`

- Looks up an IP, domain, or hash in cached threat intel data.
- Returns a normalized match object.

`_is_public_ip(ip_value)`

- Returns whether a string is a public routable IP address.

`_process_hash(pid)`

- Attempts to hash a process executable with SHA-256.
- Returns `None` if the process or file cannot be accessed.

`_current_indicators()`

- Collects live public remote IP indicators.
- Falls back to hashing a top CPU process when no public IP indicators exist.

`_decorate_threat_intel(anomaly)`

- Adds anomaly ID, indicator, threat intel match, risk score, and framework mappings.

## Anomaly Pipeline

`_anomaly_id(anomaly)`

- Builds a stable short SHA-1 identifier from anomaly timestamp, metric, value, and category.

`_framework_map(anomaly, risk_score)`

- Maps anomaly context and risk score to NIST and CIS control labels.

`_load_telemetry_df(start=None, end=None)`

- Loads `logs/system_log.csv`.
- Applies optional date filters.
- Returns a pandas DataFrame.

`_detect_stat_anomalies(df)`

- Finds CPU and memory outliers using mean plus two standard deviations.
- Assigns high or critical severity based on z-score.

`_detect_rule_anomalies(df)`

- Evaluates enabled custom anomaly rules against latest telemetry values.

`_load_anomalies(start=None, end=None, severity=None, apply_automation=True)`

- Orchestrates telemetry loading, statistical detection, rule detection, threat intel decoration, sorting, filtering, playbook matching, and automation matching.

`op_eval(value, operator, threshold)`

- Evaluates threshold comparisons for rules and playbooks.

## Automation and Playbook Functions

`apply_playbooks(anomalies)`

- Checks enabled auto playbooks against anomalies.
- Records matching playbook runs.

`automation_matches(rule, anomaly)`

- Checks whether an automation rule matches an anomaly field.

`apply_automation_rules(anomalies)`

- Applies enabled automation rules to anomalies.
- Records action history entries.

`_timeline_for_anomaly(anomaly_id)`

- Builds a root-cause timeline around an anomaly.
- Combines historical metric samples with live process and network context.

## Report Functions

`_audit_rows(limit=100)`

- Reads audit rows from the telemetry log.
- Converts rows into event-style records for UI and reports.

`_report_summary()`

- Builds report summary data from anomalies and audit rows.
- Aggregates framework coverage.

`_csv_response(summary)`

- Builds a downloadable CSV report response.

`_pdf_bytes(lines)`

- Builds a minimal PDF byte stream from text lines.

`_pdf_response(summary)`

- Builds a downloadable PDF report response.

## Terminal Functions

`_validate_terminal_command(command)`

- Parses a browser-submitted diagnostic command.
- Rejects command paths, unsupported commands, absolute paths, and parent traversal.
- Resolves allowlisted command names with `shutil.which`.

`_ws_send(sock, text)`

- Sends a text WebSocket frame.

`_recv_exact(sock, length)`

- Reads exactly `length` bytes from a socket.
- Prevents partial TCP reads from truncating WebSocket frames.

`_ws_recv(sock)`

- Receives and unmasks a browser WebSocket frame.
- Uses `_recv_exact` for headers, extended length, mask, and payload.

`TerminalWebSocketServer`

- Threading TCP server with address reuse enabled.

`TerminalWebSocketHandler.handle()`

- Performs the WebSocket handshake.
- Validates and runs allowlisted diagnostic commands without shell execution.
- Streams command output back to the browser.

`start_terminal_ws()`

- Starts the diagnostic WebSocket service.
- Called only under the runtime guard when `web/saaoe_api.py` is run directly.

## API Route Design

### Page Routes

- `/`: dashboard overview.
- `/processes`: process monitor page.
- `/analytics`: live analytics page.
- `/visualization-lab`: scientific visualization page.
- `/security`: security alerts page.
- `/audit-logs`: audit log page.
- `/ethics`: ethical AI monitoring page.
- `/files`: file classification page.
- `/terminal`: diagnostic terminal page.
- `/reports`: compliance reports page.
- `/automation`: automation rule page.
- `/assets`: local asset inventory page.
- `/threat-trends`: threat trend page.
- `/playbooks`: playbook management page.
- `/anomalies`: anomaly management page.
- `/anomalies/<anomaly_id>`: anomaly detail page.

### Telemetry APIs

- `/api/usage`: CPU and memory series.
- `/api/disk`: disk read/write series.
- `/api/net`: network RX/TX series.
- `/api/visualization_lab`: visualization-ready telemetry and risk data.
- `/api/local_machine`: host identity, resource, process, user, and network context.
- `/api/procs/top`: top process summary.
- `/api/procs`: process rows for tables.
- `/api/temps`: host sensor temperatures.
- `/api/gpu`: optional GPU data.

### Security and Workflow APIs

- `/api/anomalies`: decorated anomaly list.
- `/api/anomalies/heatmap`: anomaly density buckets.
- `/api/anomalies/<anomaly_id>`: anomaly detail and timeline.
- `/api/anomaly_rules`: custom anomaly rule CRUD.
- `/api/playbooks`: playbook CRUD.
- `/api/playbook_trigger`: manual playbook response trigger.
- `/api/automation_rules`: automation rule CRUD and history.
- `/api/security/alerts`: security alert cards derived from anomalies.
- `/api/threat_intel/lookup`: direct indicator lookup.
- `/api/notifications`: SSE anomaly notification stream.

### Reporting and File APIs

- `/api/reports/summary`: compliance report summary.
- `/api/reports/download.<fmt>`: CSV or PDF report download.
- `/api/logs`: telemetry log rows.
- `/api/audit_summary`: audit summary text.
- `/api/audit/stats`: audit count metrics.
- `/api/files/access`: cached filesystem classification results.
